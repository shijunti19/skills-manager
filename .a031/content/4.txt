这个功能到底解决什么问题？
核心痛点：技能库膨胀占用大量上下文 Token，导致 AI 响应变慢、成本升高、有效上下文变少。
在 ZCode 等支持 Skills 的 AI 编码工具中，每个 Skill（通常是一个 SKILL.md 文件 + 描述）在启动或会话时会被加载到上下文里。安装几十上百个 Skill 后，仅技能的名称 + 描述 就可能消耗几万 Token（实测案例中 2000+ 个 Skill 可达 8 万 Token，占用 40% 上下文）。
这直接导致：

长会话容易超限
每轮响应变贵、变慢
有效思考空间被挤占

解决方案：通过标签管理 + 动态生成提示词 + 同步机制，实现“按需组合、轻量加载”。只把当前需要的 Skill 指针/模板塞进提示词，剩余的通过中央库同步管理，避免全部常驻上下文。

标签管理：自定义 Skill 分类与描述
我们可以在 ZCode 的技能库里给每个 Skill 打上自定义标签（Tag），并添加清晰的标题和描述。
示例：

标题：⚙️ Rust系统开发
描述：Rust 后端/系统层开发。支持 BMAD agent 编码、快速实现、按规格落地、TDD 红绿重构。

这样 AI 就能快速理解这个 Skill 的用途，后续生成提示词时也更精确。
提示词模板（后期可直接复制使用）：
textRust 系统/后端开发用这组技能：
1. bmad-agent-dev —— 按填充好上下文的 story 文件严格实现，资深工程师级编码。
2. bmad-quick-dev —— 做小改动、bug 修复、需求调整——产出干净可运行的代码，遵循项目现有架构。
3. implement —— 按规格或 ticket 集合落地一段工作。
4. bmad-dev-story / bmad-dev-auto / bmad-create-story —— 执行 story 实现、无人值守开发循环、创建完整上下文 story 文件。
5. tdd —— 强制红→绿→重构循环。

验证：用 cargo test 验证；跨模块改动确认 API 兼容和数据流一致。

图片2（Agents 选择 / 生成提示词界面截图）
Agents 选择 + 技能标签选择

先选择对应的 Agent（或多 Agent 组合）
然后在技能库中勾选需要的 标签 或具体 Skill
AI 会自动帮你分类整理标签（你通常可以直接让 AI 生成合理的分类）

提示词生成模板
生成的提示词会使用以下格式（跨终端兼容，防止路径不一致）：
text[${{name}}]({{path}})
示例输出：
text# 🧹 上下文管理
整理压缩当前对话、生成交接文档、新开会话省 token。长会话主动用，防止上下文超限浪费 token。

[$caveman](C:/Users/52752/.skills-manager/skills/caveman/SKILL.md)
[$caveman](C:/Users/52752/.skills-manager/skills/caveman-2/SKILL.md)
[$claude-handoff](C:/Users/52752/.skills-manager/skills/claude-handoff/SKILL.md)
...（其他选中的 Skill）
你只需把这段组合提示词 发给 AI，它就能立刻调用对应的技能。

同步按钮的作用
安装大量 Skill 后，即使不使用也会占用上下文。同步功能 的机制是：

清空本地缓存目录（例如 C:\Users\52752\.zcode\skills）
从中央技能库（.skills-manager）中复制或符号链接 当前标签管理的 Skill 到本地
只加载必要的轻量指针，减少 Token 浪费

这样既保持了所有 Skill 的可管理性，又实现了按需加载。

使用流程总结（推荐直接复制给别人）：

在技能库给 Skill 打标签 + 写描述
选择 Agent + 勾选标签
点击“生成提示词” → 获得组合后的完整提示词
需要更新时点“同步”按钮，保持本地轻量

这个机制极大提升了多 Skill 环境下的效率，尤其适合重度用户和长会话开发场景。
